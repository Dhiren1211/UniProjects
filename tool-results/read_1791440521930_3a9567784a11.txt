     1→# UniProject Design System
     2→
     3→> **Visual reference:** [Flokka](https://flokka.me/)\
     4→> **Purpose:** Visual design specification for UniProject --- colors,
     5→> typography, layout, components, states, responsive behavior, and
     6→> interaction style.
     7→
     8→## 1. Design Direction
     9→
    10→UniProject should borrow the **visual feeling** of Flokka rather than
    11→copy its branding.
    12→
    13→Flokka's current landing page uses a focused student-network message,
    14→short sections, generous whitespace, strong typography, simple
    15→navigation, and clear primary actions. Its content hierarchy moves from
    16→a large statement → supporting explanation → feature/value blocks →
    17→process → final CTA. citeturn1view0
    18→
    19→### UniProject visual personality
    20→
    21→-   **Modern academic**
    22→-   **Friendly and student-first**
    23→-   **Clean rather than corporate**
    24→-   **Content-led**
    25→-   **High whitespace**
    26→-   **Strong typography**
    27→-   **Soft surfaces and rounded components**
    28→-   **One recognizable accent color**
    29→-   **Minimal decorative noise**
    30→
    31→The interface should feel like a combination of:
    32→
    33→`University archive + student portfolio + community network`
    34→
    35→not a traditional university administration portal.
    36→
    37→------------------------------------------------------------------------
    38→
    39→## 2. Brand Principles
    40→
    41→### 2.1 Content is the hero
    42→
    43→Projects, students, screenshots, technologies, and documentation are the
    44→primary visual content.
    45→
    46→Do not let UI decoration compete with project content.
    47→
    48→### 2.2 One strong accent
    49→
    50→Use one primary brand color consistently for:
    51→
    52→-   Primary buttons
    53→-   Active navigation
    54→-   Links
    55→-   Selected filters
    56→-   Important badges
    57→-   Focus states
    58→-   Small visual accents
    59→
    60→Avoid using many saturated colors at once.
    61→
    62→### 2.3 Soft neutral canvas
    63→
    64→The main page background should be a very light warm/cool neutral rather
    65→than pure white.
    66→
    67→Cards can remain white so that content feels elevated without heavy
    68→shadows.
    69→
    70→### 2.4 Typography creates hierarchy
    71→
    72→Large headings should carry most of the visual identity. Body text
    73→should remain quiet and highly readable.
    74→
    75→### 2.5 Rounded, but not playful
    76→
    77→Use medium-to-large corner radii for cards and controls.
    78→
    79→Avoid excessive "bubble UI".
    80→

   144→# 4. Typography
   145→
   146→## 4.1 Font
   147→
   148→### Primary
   149→
   150→**Pretendard**
   151→
   152→Recommended for UniProject because the product is expected to contain
   153→Korean and English university content.
   154→
   155→``` css
   156→font-family:
   157→  "Pretendard",
   158→  -apple-system,
   159→  BlinkMacSystemFont,
   160→  "Segoe UI",
   161→  sans-serif;
   162→```
   163→
   164→### Alternative
   165→
   166→If Pretendard is unavailable:
   167→
   168→``` text
   169→Inter → Apple SD Gothic Neo → Segoe UI → sans-serif
   170→```
   171→
   172→## 4.2 Font weights
   173→
   174→Use only four main weights:
   175→
   176→  Weight   Purpose
   177→  -------- -------------------------
   178→  400      Body
   179→  500      Labels/buttons
   180→  600      Card titles/subheadings
   181→  700      Major headings
   182→
   183→Avoid using 800/900 except for a deliberate marketing hero.
   184→
   185→## 4.3 Type scale
   186→
   187→  Token          Size   Line height   Weight
   188→  ------------ ------ ------------- --------
   189→  Display        56px          1.05      700
   190→  H1             44px           1.1      700
   191→  H2             32px           1.2      700
   192→  H3             24px          1.25      700
   193→  H4             20px           1.3      600
   194→  Body Large     18px           1.6      400
   195→  Body           16px          1.55      400
   196→  Body Small     14px           1.5      400
   197→  Label          13px           1.4      500
   198→  Caption        12px           1.4      400
   199→
   200→### Heading rules
   201→
   202→-   Keep headings short.
   203→-   Prefer sentence case.
   204→-   Avoid all-caps headings.
   205→-   Use `letter-spacing: -0.02em` for large headings.
   206→-   Do not use heavy shadows or gradients on text.
   207→

   210→# 5. Spacing System
   211→
   212→Use a 4px base unit.
   213→
   214→``` text
   215→4   = 1xs
   216→8   = 2xs
   217→12  = xs
   218→16  = sm
   219→20  = md-sm
   220→24  = md
   221→32  = lg
   222→40  = xl
   223→48  = 2xl
   224→64  = 3xl
   225→80  = 4xl
   226→96  = 5xl
   227→128 = 6xl
   228→```
   229→
   230→### Common usage
   231→
   232→-   Icon-to-label: `8px`
   233→-   Input padding: `12–16px`
   234→-   Card internal padding: `20–24px`
   235→-   Section gap: `48–80px`
   236→-   Major page sections: `80–120px`
   237→-   Mobile page padding: `20px`
   238→-   Desktop page padding: `32px`
   239→

   248→Preferred width: calc(100% - 40px)
   249→```
   250→
   251→For large project galleries:
   252→
   253→``` text
   254→Maximum width: 1280px
   255→```
   256→
   257→For reading-heavy documentation:
   258→
   259→``` text
   260→Maximum width: 820px
   261→```
   262→
   263→## 6.2 Desktop grid
   264→
   265→Default:
   266→
   267→``` text
   268→12-column grid
   269→24px gutter
   270→```
   271→
   272→Example:
   273→
   274→``` text
   275→[ 3 ][ 6 ][ 3 ]
   276→```
   277→
   278→Profile/project detail:
   279→
   280→``` text
   281→[ 8 ][ 4 ]
   282→```
   283→
   284→Project gallery:
   285→
   286→``` text
   287→[ 4 ][ 4 ][ 4 ]
   288→```
   289→
   290→## 6.3 Mobile
   291→
   292→Below `768px`:
   293→
   294→-   Collapse multi-column layouts.
   295→-   Use a single content column.
   296→-   Reduce horizontal padding.
   297→-   Keep primary CTA full-width where appropriate.
   298→-   Convert filter bars into horizontal scroll or a filter sheet.

   338→# 9. Shadows
   339→
   340→Keep shadows subtle.
   341→
   342→### Card
   343→
   344→``` css
   345→box-shadow:
   346→  0 1px 2px rgba(20, 20, 30, 0.04),
   347→  0 8px 24px rgba(20, 20, 30, 0.05);
   348→```
   349→
   350→### Floating element
   351→
   352→``` css
   353→box-shadow:
   354→  0 12px 32px rgba(20, 20, 30, 0.10);
   355→```
   356→
   357→Avoid large dark shadows.
   358→
   359→Prefer borders + very soft shadows.

   439→Use only for irreversible actions.

   451→Pressed
   452→Focus

   510→# 14. Project Card
   511→
   512→Project cards are one of the most important components in UniProject.
   513→
   514→### Structure
   515→
   516→``` text
   517→┌─────────────────────────────────────┐
   518→│ [Project image / screenshot]        │
   519→│                                     │
   520→├─────────────────────────────────────┤
   521→│ Project Title                       │
   522→│ Short project description...        │
   523→│                                     │
   524→│ [Web] [AI] [React]                  │
   525→│                                     │
   526→│ 👤 Creator Name · 2026              │
   527→└─────────────────────────────────────┘
   528→```
   529→
   530→### Required visual information
   531→
   532→Prioritize:
   533→
   534→1.  Project thumbnail
   535→2.  Project title
   536→3.  Short description
   537→4.  Technology/category tags
   538→5.  Creator/team
   539→6.  Year
   540→7.  Optional status
   541→
   542→### Do not overload the card
   543→
   544→Do not show the entire documentation, repository URL, every technology,
   545→or long descriptions on the card.
   546→
   547→Those belong on the project detail page.
   548→

   927→# 27. Motion
   928→
   929→Animation should feel calm and fast.
   930→
   931→### Standard duration
   932→
   933→``` text
   934→Fast: 120ms
   935→Normal: 180ms
   936→Slow: 260ms
   937→```
   938→
   939→### Easing
   940→
   941→``` text
   942→ease-out
   943→```
   944→
   945→Use motion for:
   946→
   947→-   Card hover
   948→-   Menu opening
   949→-   Filter transitions
   950→-   Modal/sheet entry
   951→-   Toasts
   952→-   Page-level content appearance
   953→
   954→Avoid:
   955→
   956→-   Large bouncing animations
   957→-   Continuous decorative animations
   958→-   Excessive parallax
   959→-   Slow page transitions

   961→Respect:
   962→
   963→``` css
   964→@media (prefers-reduced-motion: reduce)

  1036→# 29. Accessibility
  1037→
  1038→Minimum requirements:
  1039→
  1040→-   WCAG AA contrast target
  1041→-   Keyboard navigation
  1042→-   Visible focus states
  1043→-   Semantic HTML
  1044→-   Labels for all form inputs
  1045→-   Alt text for meaningful project images
  1046→-   Decorative images marked appropriately
  1047→-   Never use color as the only state indicator
  1048→-   Minimum touch target around `44 × 44px`
  1049→
  1050→Text contrast should generally target at least **4.5:1 for normal text**
  1051→and **3:1 for large text/UI requirements**, consistent with common WCAG
  1052→AA guidance. citeturn0search1turn0search4

  1220→# 33. Do / Don't
  1221→
  1222→## Do
  1223→
  1224→-   Use large whitespace.
  1225→-   Use strong typography.
  1226→-   Keep cards clean.
  1227→-   Use one primary accent.
  1228→-   Show project screenshots prominently.
  1229→-   Make creator identities visible.
  1230→-   Keep metadata compact.
  1231→-   Use subtle borders and shadows.
  1232→-   Make filtering easy.
  1233→-   Maintain consistent spacing.
  1234→
  1235→## Don't
  1236→
  1237→-   Do not copy Flokka's exact logo, branding, illustrations, or
  1238→    proprietary visual assets.
  1239→-   Do not use a rainbow palette.
  1240→-   Do not turn every card into a colorful gradient.
  1241→-   Do not use excessive shadows.
  1242→-   Do not put huge amounts of metadata on cards.
  1243→-   Do not make every page look like a social-media feed.
  1244→-   Do not use all-caps text everywhere.
  1245→-   Do not rely on hover as the only way to reveal information.
  1246→-   Do not sacrifice readability for visual effects.
  1247→
